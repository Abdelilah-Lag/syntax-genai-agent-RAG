COMPONENT NOTES

How the system works

Planner & tool registry

The planner requests a structured JSON plan, which is validated against the local drug catalog and tool rules. Search runs for every step; the planner may select extract, compare, interaction, glossary or verify when appropriate.

Hybrid retrieval & EvidenceStore

The in-memory retriever combines dense cosine similarity (when embeddings are available) with BM25 lexical ranks using Reciprocal Rank Fusion. Section-aware passages are deduplicated in EvidenceStore and assigned stable IDs for the answer draft.

Generator & source attribution

The answer writer receives the question, plan, tool notes and numbered evidence. Finalization maps evidence IDs to document and section citations, then exposes cited sources and retrieved passage metadata.

Critic & bounded revision

Deterministic citation and number checks complement LLM claim review. A revise verdict can trigger at most one answer revision; unavailable review is represented separately from a computed grounding score.

API layer & telemetry

FastAPI exposes /ask, /health and /metrics. Operational metrics are process-local, bounded in memory and exclude question/answer text; they reset when the process restarts.
